# Live operator runbook

The example policy has live execution disabled and leaves all financial limits for the operators to specify. Only `run live` loads the dedicated key and direct RPC transport. The live tests use an in-process RPC stand-in and deterministic test keys. Mainnet transaction submission and deployed program behavior have not been validated.

1. Review the paper replay and forward paper results before enabling live execution. Reconcile the fill and fee assumptions against public-chain examples at the intended position size. Review the locked dependencies and confirm that the pinned instruction/account layouts still match the deployed Pump and PumpSwap versions.
2. On the Linux service host, provision a dedicated Solana CLI-format keypair JSON outside the repository. Use a service user that owns the file and a mode of `0600`. Disable crash dumps for the service. Create its ledger directory with mode `0700`. Use a dedicated wallet with scoped funds, and leave the wallet’s wrapped SOL ATA absent so the PumpSwap trade can create and close it in one transaction.
3. Copy `config/live.example.json` to a private policy file. Resolve the allowlist path relative to that copy, or use an absolute path. Set the expected cluster genesis hash, wallet address and the RPC/WS environment variables named in the policy. Choose a trusted provider with enough confirmed block capacity for the monitor and finalized transaction history for reconciliation. Review the on-chain fee recipient and buyback recipient lists before entering their public keys into the policy. Only recipients in both the policy and the on-chain configuration qualify.
4. Enter all caps and rules. Lamport values are quoted decimal strings and basis points, timings and counts are JSON integers. Include the maximum network fee and potential refundable account deposit in the max entry cap. The wallet balance and exposure caps include reserves for execution. The daily loss calculation marks open positions at zero and includes realized proceeds and failed transaction fees. Keep the loss budget smaller than the amount funded and reserve enough SOL to pay for exits. Simulator and network fees must fit the policy even for a risk-reducing exit.
5. Set `enabled` to `true` only after review. Start the service with `npm run bot -- run live --config /path/to/live.local.json`. A fresh ledger starts paused. Use `npm run bot -- status --db /path/to/shahinibot.live.sqlite` in another terminal to verify the service wallet, balance, feed state, checkpoint and pending attempts. To enable entries, use `npm run bot -- control resume --db /path/to/shahinibot.live.sqlite`. Use the equivalent `pause` command to stop entries temporarily. Use `kill` to latch the entry halt durably. The service continues trying full-position exits under those controls.

The service submits only SOL curve buys and curve or canonical SOL PumpSwap sells. The standard Pump v2 curve instructions use max spend and min proceeds on-chain. Canonical PumpSwap exits use its v2 sell. The Token-2022 route accepts self-referencing metadata pointers, token metadata, and immutable owners on token accounts. Transfer-affecting or unknown extensions, active mint/freeze authority, and special modes such as mayhem, cashback, and holder rewards require review. A missing route, limit failure, RPC failure, or expired attempt can leave exposure open. Inspect the live status and compare with finalized wallet state.

An optional `rules.exits` policy freezes the TP targets and stop when a new
position fills. The live ledger stores pending and confirmed leg quantities.
One ambiguous sell blocks a second sale for the same mint. If a stop latches
while a TP is unresolved, the engine keeps checking the original signature
and sizes the terminal order from the reconciled remainder. Legacy positions
continue to use the single-exit rules. The new ladder has only been exercised
against mocked RPC in this milestone. See [exit settings and units](MILESTONE.md#configure-exits).

On startup, the service checks persisted unresolved signatures before considering new entries. An acknowledged RPC response is pending. A timeout or inconsistent finalized metadata blocks entries until reconciliation. Signed bytes can be rebroadcast within the original limit and validity window. An expired signature with inconclusive archival history is ambiguous, so the service never signs a replacement on that basis. For manual recovery, pause entries, compare the exact signature and finalized wallet/token balances using an independent archival provider, then restore the provider or review the position with both operators. Preserve the ledger and its WAL. Do not delete a pending attempt or change its signature.

If a crash leaves a `.writer.lock` beside the ledger, confirm that the recorded process ID no longer belongs to a running service and that no other service is using that ledger before removing the stale lock. Restart with the same official cluster, dedicated wallet, and ledger. A kill remains latched across restarts. To review a latched ledger with open or unsettled exposure, keep using that ledger until both operators have reconciled it.

Primary interfaces used for the live path are the [Pump SDK](https://www.npmjs.com/package/@pump-fun/pump-sdk/v/4.3.1), [PumpSwap SDK](https://www.npmjs.com/package/@pump-fun/pump-swap-sdk/v/2.2.0), [Solana simulation RPC](https://solana.com/docs/rpc/http/simulatetransaction), and [Solana submission RPC](https://solana.com/docs/rpc/http/sendtransaction).
